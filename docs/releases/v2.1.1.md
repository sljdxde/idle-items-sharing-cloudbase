# v2.1.1 发布说明

> 发布日 2026-10-23 · 对比基线 v2.1.0 · 本次 7 个提交（含两轮批量缺陷修复）

一次以「稳定性与隐私」为主题的维护版：修掉 15 处真实缺陷，把两个写通道的重复实现收敛成共享领域层，
并补上 39+ 例单元测试。功能层面没有破坏性变更，可平滑升级。

## 新功能

- **三主题 UI 系统**：`html[data-theme]` 支持 `memphis`（拼贴）/ `brutalism`（功能网格）/ `editorial`（暖色出版），全部走 CSS 变量，组件内用 `[data-theme="x"]` 段落做差异化。
- **账号体系（ADR-0005）**：手机号 + 6 位 PIN 换取 JWT（7 天），前端只解 payload 取 `phoneHash`，写操作带 `Authorization: Bearer`；旧的 `linli_haowu_user_v1` 本地模型废弃。

## 缺陷修复

### 第一批（高危优先）

- **「我的发布」列表被整块吞掉**：租金统计条的 `v-if` 与列表的 `v-else` 互斥，名下有收费物品时列表（含下架/删除入口）直接消失。
- **lent 标签成单一真相源**：标签写失败会让物品永久卡在「已借出」。改为以数据块 `borrowerHash` 为准，归还顺序调整为「先摘标签再清数据块」，标签写入失败重试一次。
- **图片预算口径错**：原按文件字节 100KB 放行，base64 后必然超过服务端 `IMG_DATA_MAX=56000` 字符而被拒。统一改为按 data URI 字符数计算（客户端 52000）。
- **管理员重置绕过 API_PROXY**：Pages 下相对路径 `/api/*` 不存在，重置请求打空；同时补 CORS 的 `x-admin-token` 与弱口令校验。
- **空列表被当读取失败**：导致已删除物品在刷新后「复活」。`fetchLive` 不再把 `[]` 变成 `null`。
- **过期 token 仍算身份 / 隐私模式下 token 只存内存**：`phoneHash` 增加过期判断，新增 `src/lib/session.ts` 作为 token 的内存单一真相源。
- **详情页深链误报「没有这件物品」**：直接打开 `/item/123` 时首屏数据未就绪，补 `settling` 加载态等一次 `load()`。
- **已下架物品联系方式对陌生人可见**：前端按归属遮蔽。
- **游客看不到「我的发布 / 我的借用」入口**：`MyPanel` 去掉登录门槛，游客可见。

### 第二批

- **已下架物品联系方式真外泄（服务端）**：`GET /api/items` 曾匿名返回全部 `contact`，直接 curl 就能拿到。新增 `redactArchived` / `redactListForCaller`，两个写通道按调用者 `phoneHash` 裁剪；`gen-items.mjs` 生成的快照同样打码。
- **借用并发互相覆盖**：读-判断-写没有版本校验，两人同时借同一件会覆盖 `borrowerHash`。改为 `ETag` + `If-Match`，412 转业务 409「手慢了，这件物品刚被邻居借走」。
- **限流内存无回收**：Worker 内 `hits` Map 只增不减。抽出 `cloudflare-worker/rateLimit.js`，按窗口定期 sweep。
- **快照映射漂移**：Node 侧自抄的 `toItem` 丢了 `rentType` / `rentFee` / `rentRecords`，导致「从快照读到的物品全是免费、租金统计恒为 0」。统一走 `cloudflare-worker/items.js`。
- **图片长度常量与服务端不一致**：`safeImage` 上限对齐为 `56064`（= `IMG_DATA_MAX + 64`）。
- **6 格 PIN 输入框快速输入字符错位**。

## 工程与发布

- 两个写通道（Cloudflare Worker / Pages Function / 自建 Node）的映射、状态语义、裁剪、限流原语收敛到 `cloudflare-worker/items.js` 与 `rateLimit.js`，不再各抄一份。
- 写后对账支持 `?fresh=1` 绕过代理端 5s 列表缓存；乐观写 `pendingWrites` 增加 60s TTL。
