1. 目标与架构决策

  • 已上线文字：本地敏感词过滤（免费、无限、不可绕过），覆盖黄赌毒/暴力违禁文案；
  • 已上线图片格式：本地魔数校验（jpeg/png/webp），拒绝伪造图片；
  • 本次图片画面：可插拔 Provider 接口 + 本地 NSFWJS 自托管（免费、无限、数据不出站）；
  • 已放弃百度 AI 内容审核（5000 次/30 天、需续期）与额度台账机制 —— 改为本地无限方案后不再需要额度管理。
设计原则：图片检测做成接口（Provider），当前用 NSFWJS，将来可随时替换为 NudeNet / ShieldGemma 等更好的开源库，业务代码零改动。

2. 审核链路（发布时序）

发布请求 POST /api/items
① 基础校验 已有 — 长度 / 手机号 / 分类 / 联系方式
② 文本敏感词 已有 moderation.js（本地）→ 命中直接 400
③ 图片格式魔数校验 已有（本地）→ 非法 400
④ 若带图：图片画面审核 本次 auditor.audit(imgUrl)（Provider：nsfwjs）→ 违规 400；服务不可用 502（安全失败，不误放行）
⑤ 落库 GitHub Issues 已有

3. 图片审核 Provider 接口（可插拔）

cloudflare-worker/imageAudit.js 定义统一契约：

// 每个 Provider 实现：
{ name: string, audit(imageDataUrl) → Promise<Result> }

// Result:
{ pass: true }                      // 通过
{ pass: false, reason }             // 违规，拒绝
{ error }                           // 失败/未配置 → 安全失败（拒绝该次、不误放行）

// 选择 Provider：
createAuditor(mode, deps)
  'mock'   → 测试/CI 专用
  'nsfwjs' → 本地 NSFWJS 服务（默认）

新增更好的开源库：写一个 createXxxAuditor(deps) 实现上述契约，在 createAuditor 的 switch 加一行即可，业务代码零改动。

4. NSFWJS 自托管服务

  • 独立服务 server/nsfwjs-server.mjs（Node + @tensorflow/tfjs-node + nsfwjs），监听 127.0.0.1:8090；
  • 判定：Porn + Hentai + Sexy 概率和 > 阈值（默认 0.4）→ unsafe；
  • 接口协议：POST /audit-image { image: base64 } → { ok, unsafe, score }；GET /health；
  • 模型：首次自动从 nsfwjs 托管地址下载（约 20MB），之后常驻内存；
  • Worker 通过环境变量 NSFWJS_URL 指向该服务的公网地址（nginx 反代或 Cloudflare Tunnel 暴露）。
部署依赖：服务需运行在可公网访问的常驻机器上，详见 docs/NSFWJS服务部署.md。

5. 性能与开销

环节位置延迟成本说明
文本敏感词Worker 本地微秒级0可忽略
图片魔数Worker 本地1–3 ms0可忽略
画面审核（NSFWJS）本地服务器100–500 ms + 网络0（无限）模型常驻；发布低频，可接受
落库 GitHubWorker → GitHub500 ms – 2 sGitHub API原逻辑

要点：无图发布不受影响（不调审核）；带图发布新增约 0.3–1s（一次本地审核+网络）；审核服务不可达时安全失败（拒绝该次），不影响浏览/列表性能；不依赖任何第三方额度，无配额耗尽问题。

6. 测试与 Mock 策略

原则：自动化测试永不触发真实审核。

  • 审核客户端接口化：测试注入 mock Provider 或 stub fetch，断言“未向审核服务发请求”；
  • imageAudit.test.ts：mock/nsfwjs 各分支（通过/违规/未配置/网络错误/超时/请求体）；
  • NSFWJS 服务本体：部署后一次性手工冒烟（/health + 正常图 unsafe=false），本机已验证通过；
  • 测试套件 203/203 通过，全程 0 外部调用。
